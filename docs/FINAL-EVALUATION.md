При таймауте режим `fallback` не засчитывался как успешный вызов инструмента модели, даже если карточки совпали. Все 13 строгих неуспехов повторного прогона относятся к таким таймаутам. Расход у запросов без ответа неизвестен; сумма `usage` может быть неполной.

В [первом прогоне](reports/assistant-final-own-initial-2026-11-14.json) было 48/60. Обнаружены и исправлены:

- Обычный поиск принимал слово «городе» за часть названия, когда модель не отвечала. Добавлено корректное удаление фразы «в городе» при распознанном городе и регрессионная проверка.
- Измеритель Telegram выбирал трассу по времени, одинаковому для всех реплик при фиксированных часах. Теперь он получает именно новую трассу текущей реплики. Это ошибка измерителя; реальное условие бесплатного входа бот сохранял.
- При проверке хранения выяснилось, что диагностическая запись использовала системные часы, а диалог — переданные сервису часы. Устранено расхождение, полный набор 95 проверок прошёл.

Исходный отчёт сохранён, лучший запуск не выбирался вместо последнего. Повторный результат режима модели хуже из-за большего числа таймаутов внешнего endpoint. Порог p95 ≤6 с уровня 4 не достигнут. Отдельная последовательность 20 HTTP-запросов с явно отключённой моделью на PostgreSQL прошла без 5xx, с карточками резервного поиска.
