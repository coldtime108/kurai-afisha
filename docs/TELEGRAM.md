# Telegram: подготовка и запуск

Бот реализован на aiogram 3.31.0 и пользуется теми же сервисами каталога, что API. По решению пользователя живой бот пока не создаётся и не подключается. Сценарии проверяются полностью без внешней сети через настоящий Dispatcher и подставной Telegram-транспорт.

## Подключение позднее

1. В Telegram открыть официальный `@BotFather`, создать бота командой `/newbot`, выбрать имя и свободный username.
2. Сохранить выданный токен в локальном `.env` проекта как `TELEGRAM_BOT_TOKEN=...`. Не отправлять токен в чат, не добавлять его в Git и не помещать в URL.
3. Когда Docker доступен, выполнить из корня:

```sh
docker compose --profile telegram up --build
```

4. Открыть своего бота, нажать Start, проверить `/start`, поиск, карточку, подтверждение подписки и `/unsubscribe`.

Без Docker: задать `DATABASE_URL`, `PYTHONPATH=backend` и `TELEGRAM_BOT_TOKEN` в окружении процесса, применить миграции, затем `python -m kurai.telegram_worker`. Сам worker не читает `.env` автоматически. В Docker Compose файл загружается самим Compose.

Если у существующего бота настроен webhook, worker откажется запускать polling. Он не отключает чужой webhook и не меняет конфигурацию бота автоматически.

## Пользовательские сценарии

- `/start` — короткое приветствие и меню; `/help` — помощь.
- Афиша: карточки по 3, «Показать ещё», выбор города/категории, сегодня/завтра/выходные, свободный запрос. Пример: «Концерт в стерлитакмае в субботу до 1000 рублей».
- Время — по Башкортостану, UTC+5; цена — минимальная цена одного билета. Нет обещания групповой стоимости и наличия мест.
- Карточка: факты из БД, возраст, адрес, длительность/язык при наличии, ссылки на источники; явная пометка отмены. Черновики не доступны.
- `/subscribe` — предварительный просмотр города и категории, затем отдельная кнопка подтверждения. Подтверждение связано с пользователем, одноразовое и действует 10 минут.
- `/unsubscribe` — удаление подписки, отложенных отправлений и приватного состояния. Команда доступна даже при превышении лимита запросов.
- `/feedback` — текст обращения, предварительный просмотр, подтверждение отправки в очередь модератора.
- `/cancel` — отмена незавершённого действия.

Диалоги работают в личных чатах. Группы и callback от чужого приватного чата игнорируются. Имя пользователя, username и телефон не сохраняются. Временное состояние поиска хранится 24 часа; подписка — до 180 дней. Обращение — до 30 дней. Фоновая очистка в API выполняется каждый час.

## Дайджест

Не чаще одного дайджеста в день, в 18:00 по времени Башкортостана. Включает до трёх новых опубликованных событий выбранного города/категории в ближайшую неделю. Если новинок нет, сообщение не отправляется. Существующие записи сразу после подписки не выдаются за новые.

Очередь хранится в БД, переживает перезапуск. Ошибка доставки сохраняется; до трёх попыток с задержкой, с учётом Telegram Retry-After. При блокировке бота подписка удаляется. Перед отправкой заново проверяются статус, город, категория и даты. Один процесс worker на контур; для нескольких нужна отдельная система распределённых блокировок.

Telegram не предоставляет ключ идемпотентности отправки: при сбое после успешной передачи сообщения, но до фиксации результата в БД, повторная доставка возможна. Очередь обеспечивает повторяемость обработки, а не обещание exactly-once.

## Текущая граница

Это детерминированный бот каталога, без LLM. Уточнения «подешевле», многошаговый агент, формальные инструменты и трассы остаются следующей контрольной точкой. Живой обмен с Telegram и доставку настоящего дайджеста нужно проверить после подключения токена; офлайн-проверки не заменяют эту проверку.
